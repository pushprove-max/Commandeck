## Data design

- `$PP_SCRATCH/unit-events.jsonl` (C21, new): one `{"at":"<iso>","unit":"<unit>","event":"<event>"}` line per seat-launch, seat-verdict, codex-start, codex-end, merge. - `$OUT/.live/<project>/` (C22, new): that follower's per-unit run records; removed with `$OUT`.
- `$CACHE/<project>/unit-events.gen` (C22, new): one line `<generation> <stream size> <cksum of the 256 bytes before it>`, with `unit-events.gen.lock` beside it. One owner, `seen_mark`, the one reader and writer, under flock, temp file then rename; every collect and fast-lane run calls it before it reads a source. Each run's `seen` is `{gen, seq (the size), at}`. It resets when the stream is shorter, rewritten or replaced, or the record is lost or malformed: a new generation, later than every earlier, so no mark of the old stream compares as newer. A lock not taken in 10 s, or a failed write, fails that run; the next run or event retries, and the next cycle's mark stands.
- `$CACHE/<project>/unit-stages.json` (C22, changed): each unit's record gains `seen`, the mark of the run that wrote it. One writer, the full cycle; the fast lane reads it and never writes. A record and a live row of this run's generation compete for the stage's start, the larger sequence winning, the record on a tie; a record of another generation counts for nothing, so its stage time starts again. An unreadable unit list leaves the file as it was. A lost file loses the stage times, which restart at the next cycle.

## Protocols

- Revision generation: a generation identifier, the new task id, no fingerprint. Every route's prompt holds it: Orca's preamble, the typed ` Task id <new>.`, the pointer's `<new>.md` (seat.sh:560, dispatch-task.sh:61-65). read-verdict.sh binds `--task` on user text rows only (:131-134), so `session=` appears only once that prompt landed.
- Same second: no epoch is compared, so `>=` is gone and `>` is not used; read-verdict.sh:784's floor cannot pass an old prompt or miss a new one.
- `end_wait`: count `$LOG`'s assistant rows; send Escape; `rm -f "$CLAIM"` at once, as :229 does, since ask-main.sh's EXIT trap waits on a held claim (:60-64); poll up to `ANSWER_WORKER_ESCAPE_WAIT` s (default 10).
- Wait ended, all four: the claimed pid gone; `pending_state parked` and `working` both no on a fresh `log_state`; assistant rows unchanged; `pane_is_busy` returns 1. Only then the hand-off runs.
- A miss: return 1, no /clear, no hand-off, today's route; a live wait takes the reply (:211 set the id). No Builder decision.
- `--answer`: bypasses the added-scope guard at builder-add-work.sh:36 (an answer adds no scope), :37's rulings check, the probes (:39-45) and the stop note (:61-63). Ordinary added work keeps all of them, `--small` included.
- Case, Escape missed: as P2 parked, the pid lives or an assistant row appears -- no /clear, the reply lands in the thread -- a failed Escape keeps the reply (issue 478)
- Case, after pass 1: `builder-add-work.sh u --answer 'yes'`, `u-r1-reports.md` present, no `--small` -- exit 0, a hand-off; `--unless` work there still exits 2 -- an answer after pass 1 goes fresh (issue 478)
