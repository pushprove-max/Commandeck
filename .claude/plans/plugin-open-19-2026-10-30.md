## Data design

- `COMMANDECK_SYNC_FETCH_S` (C1, new env, default 60): read only by `pp_sync_main`. No file.
- `MERGE-TIME` lines (C2, new, merge log on stdout): `MERGE-TIME step=<name> start=<epoch> end=<epoch> seconds=<n>`, then `MERGE-TIME total seconds=<n>` just before DONE, so DONE stays the last line. One writer under the merge lock; nothing parses them. A failed merge closes its open step and prints no total: that absence is the sign. Exit 3 (merged, a later step failed) prints no total either. `MERGE_T0` is internal, blank on a dry run.
- `$HOME/.commandeck/shell-test-seconds.tsv` (C3, new; `COMMANDECK_SHELL_TEST_SECONDS` overrides the path): `<seconds>\t<file basename>`, one copy per host; run-shell-tests.sh is the one writer and reader.
  - A row for a deleted file is dropped at the next save. A file with no row starts after the known ones, in sorted order.
  - A row not matching `^[0-9]+\t[^\t/]+$` is skipped. An unreadable file means sorted order and one stderr line.
  - Each save merges this run's rows into a temp file and renames it. A failed save prints one line and never changes the exit.
  - Only a whole-scope run saves. A run under `COMMANDECK_RUNNING_TEST` neither reads nor writes unless the path variable is set. The clear-out at :71 unsets that guard, so `NESTED` takes it above the loop; the path variable survives by its `COMMANDECK_SHELL_TEST_` name.
- `.githooks/pre-push` (C5, new, tracked, outside the plugin folders): one script, wired per checkout by `core.hooksPath`. Writes a detached temp worktree, removed on every way out.
- `Test edit: <path> ruling:<id>` lines (C11, new) in main's `<unit>-main-rulings.md`: main the one writer, only main's copy counts, the id checked by `ruling_id_ok`. A malformed line approves nothing. After a new line the Builder runs `--ack-rulings` again; the refusal says so. The merge archives the file.
- `Review workflow: default` or `Review workflow: per-issue #a #b` (C12, new): one line in the batch, so in main's `<unit>-builder-brief.md`, the only copy read by the pass, `--verify` and the dashboard. No line or no file is the default. A malformed or doubled line refuses.
- `review-limits.perIssueRegular` (C12, new, 3): read through `pp_review_limit`; its reader refuses 0.
- `Per-issue #<n> round <R>: continue|redesign` (C13, new): main's answer in main's rulings file. Any other shape on such a line refuses; the worktree's copy is ignored.
- `<unit>-issue-<n>-round-<R>.md` with `-prompt-<k>.md` and `-codex-<k>.json` (C13, new, in the unit's briefs). The round file is written only after a verdict. The issue base is where the previous issue's last review ended, else the review base, read from the issue's first non-cut row. Rerunning the command after a cut resumes: nothing new commits, the next round comes from the session rows.
- Session heads `HEAD_ISSUE_ADV`, `HEAD_ISSUE_REV`, `HEAD_ISSUE_DESIGN` (C13, new): listed only when `ISSUE_SET` is on, so the final record, the cap count and `--verify` never see them. `ISSUE` and `ISSUE_SET` are unset at start, so a pane's env cannot hide a row.
- `result.json` (C15, added keys): `context_sources`, `cache_expiry`, `main_share`, `finding_value`, `after_merge`, `passes[].usd`. Old files still render.
