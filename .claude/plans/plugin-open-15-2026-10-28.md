## Data design

- Driver lock: `$PP_SCRATCH/drive-<unit>.lock` (a `flock` file, fd 9) and `$PP_SCRATCH/drive-<unit>.owner` (the service name). Admission and takeover are one critical section: start takes `flock -w 60 9`, reads the owner, takes over only when `hs_active` returns 1 (2, unknown, refuses naming the owner), writes its own name, starts the service with fd 9 closed, and releases. run takes `flock 9` for its whole life and runs only if the owner file still names it, so a start that lost the race runs nothing. run removes the owner file on exit; the lock frees when fd 9 closes.
- Driver stop line: `$PP_SCRATCH/unit-loop-<unit>.done`, one `STOP unit=<u> stage=<s>: <why>; next: <command>` line. Written by the driver on a stop. The driver sends it once to main's run, and a fresh start clears it. On `No plan` it reads `STOP unit=<u> stage=tier: No plan; next: builder-launch.sh --skip-plan --reason '<its launch: reason>' <unit> <batch>` (the reason from plan-tier.sh's `launch:` line); the driver starts no seat or Builder and exits.
- Driver launch mark: `$PP_SCRATCH/drive-<unit>.launched` (epoch). builder-launch.sh writes it when COMMANDECK_DRIVER=1 and removes it on a hand launch. main-watch.sh reads it to settle routine round reports unsent.
- Rulings gate (builder-launch.sh:186): main's newer rulings stand in for a revision only on J, the newest judge record on the plan, when it is that plan's only judge record (:187-192, kept) and is `seat-<unit>-plan-judge-sol.txt`, or `seat-<unit>-plan-judge-fable.txt` while `pp_role_enabled plan-judge-sol` returns 1 (Sol off, so plan-tier.sh selects Fable alone). Return 2 stops the launch naming the key, as :156-158. The :128-129 messages name J's `role=`, so Sol's text is unchanged.
- Stage state: none new. Each stage is skipped when its seat record (`seat-<unit>-<role>.txt` verdict=/collected=) already holds its result, so a retry resumes.
- Issue cases: read live from `gh issue view <n> --json body` on each plan-check run. Nothing is cached.
- Brief commit (#448): one commit on the unit branch, only when `.claude/briefs/<unit>.md` is tracked there. A relaunch commits only a changed brief.
- No other state is added or changed. The codebase-memory scratch cache `graph-project` loses its only writer (D5).
