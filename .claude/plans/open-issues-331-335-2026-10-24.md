## 2. Issue 333: the prototype and the port

What the prototype does (one hooks module, about 150 lines): on `session.start` in the relay seat it registers
`/maxauto`, restores the band from `$.store` (`mode`, `lastCount`) and sets the status line. `on` writes a dated
markdown log with a fixed head, stores `{log, since}`, opens the log in an Orca tab and injects a context line telling
the seat to handle the open decisions now. `off` stores the final count, deletes the mode, stamps the end time on the
log and asks for a short account. `prompt.compose` adds the rules section while on. A `tool.call` hook recounts `### `
entries after any Bash, Edit or Write of a `.md`. A second `tool.call` hook denies AskUserQuestion while on, with a
`.catch` that lets it through. `ui.render AbovePrompt` draws the band.

What the port changes to fit the plugin:
- Name: `/autodecide`, atoms `{plugin: 'commandeck', key: 'autoDecideSince' | 'autoDecideCount'}`, section id
  `autodecide:rules`; `PluginState` in `types/index.d.ts` under `commandeck`.
- Paths: no fixed folders. The main checkout comes from `git -C <session root> rev-parse --path-format=absolute
  --git-common-dir` (the way `hooks/worker-ask-guard.sh:19-20` tells seats apart). The log is
  `<main>/.claude/metrics/autodecide-<YYYY-MM-DD-HHMM>.md`, beside the decisions ledger; `autodecide.on` beside it
  while the mode is on, so the shell side (`relay-order.sh --auto`) can see the mode.
- Seat gate: relay = session root's basename is `Chief-of-Staff` under the workspaces folder (`scripts/paths.sh:499`);
  main = session root is the main checkout. Each is gated by `autoDecideSeats`. The store key is `mode:<main>`, so two
  projects on one machine never share a mode.
- Words: the owner, main and the relay, never a name. Every decision the seat makes goes through
  `scripts/relay-order.sh --auto` (section 1), which logs, records and tells main in one step.
- Time: the machine's local time from `date` (the prototype pinned one time zone).
- Loaded in every session through the plugin's `hooks/hooks.json`, gated by seat, so a fresh session keeps the
  command and the band.

Left out, and why: the prototype's append to a host report index (the plugin has no such index); its fallback that
appends to a host-only seen-decisions file (the plugin's `decision.sh` is the ledger); its host-specific never-decide
items (product score lines, one customer, production reads), replaced by the issue's generic default list plus
`autoDecideNever`.

## 7. Established practice for the security-relevant changes

- Writing user settings files (issue 334, F13, F14, F17): read-modify-write that keeps every key it does not own, a
  record of what was there before, an exact undo, and no write outside the file the user's session reads. The plan
  follows it through the existing `il_*` helpers (`il_record`/`il_write`, manifest under the install folder,
  `il_profiles_out` on uninstall). The session-start repair writes only the active profile's file, only keys the
  manifest says setup set there, and never the shared home file under a profile; no new writer.
- An agent deciding for the owner (issue 333): explicit opt-in that only the owner turns off, a visible indicator,
  a log written before each action, human approval kept for irreversible or outward actions, every decision reported
  to the human, and fail-safe to asking. The plan follows it: `/autodecide on|off`, the band and status line,
  `relay-order.sh --auto` logging, recording and telling main in one step, the hard limits under "Waiting for the
  owner", the owner's `autoDecideNever` kept through setup and update, and the guard failing open to the picker. Gap,
  stated: the hard limits and the never-decide list are instructions to the model, not code; `--auto` checks only that
  the mode is on. A push or deploy is still stopped only by the plugin's existing git and Bash guards, which this
  unit does not change (not checked against every limit).

## 8. Catches (each added flow step)

- ask-main wait. Catches: a wait that returns old unacknowledged messages at once, or another question's answer.
- ask-main resume state. Catches: a resume that replays acked messages or restarts the 9-minute clock.
- ask-main other messages. Catches: an acked message the Builder never reads.
- to-main id line. Catches: a question whose reply cannot be matched.
- `main` rebound at handoff, and the no-live-pane send queued. Catches: a Builder's question lost to a closed main pane.
- Pass ticker. Catches: a live pass taken for a hung one.
- Profile repair at session start. Catches: an Orca launch undoing setup.
- Doctor repaired-file line. Catches: settings lost and restored with nobody told.
- Wake-log line per wake exit. Catches: a missing wake with no trace.
- Watcher log cap. Catches: an unbounded log filling the disk.
- Repeat-failure alert on the streak start. Catches: a watcher failing for hours unseen.
- Doctor no-pane FAIL. Catches: a watcher that never found main.
- Audit file discovery. Catches: a stale rule in a template, brief, doc or hook.
- Rules-audit CI step. Catches: a template naming a retired or unknown option.
- Auto-decide picker guard. Catches: a seat waiting on a picker nobody answers while the owner is away.
- Auto-decide seat gate. Catches: main (or another project) reading a mode it was not given.
- `relay-order.sh --auto`. Catches: an auto-decision main never hears of, or one with no trace in the ledger.
- `autoDecideNever` kept by setup. Catches: a re-run removing the owner's own hard limits.
- ask-main clamped slices and ack on success. Catches: a wait past its deadline, or an answered batch replayed.
- Repair from `optionsWant`. Catches: an explicit option replacement lost at the next Orca launch.
- Streak cleared only by `turn_started`. Catches: watcher reposts hiding a pane that is never woken.
- Main's auto-decided instruction. Catches: main refusing every delegated answer, or skipping the ruling check.
- `il_main_lean`. Catches: main's lists cut in a worker too, or an owner's own setting lost at uninstall.
- `--active-index` at main's start. Catches: archived memories still loaded at every start.
- D1 cuts. Catches: main woken for news it never acts on.
- D2 every-ordering prompt, second-return design fix, third-return redesign. Catches: one ordering bug per pass.
