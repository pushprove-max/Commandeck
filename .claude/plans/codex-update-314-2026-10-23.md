## Decisions (ponytail ladder: the rung each part stopped at)

- Config key: rung 2, the existing `il_notify_set` rewrite (one locked write, one stat check, one plan diff). Rejected
  lazier: a second writer for the key (a second lock loop and a second race with 315's trust writes). Rejected:
  a manifest flag for uninstall; the line carries a marker comment instead, so uninstall strips the exact line as it
  strips the exact notify line.
- Key presence: rung 2, `tomllib` (already the plugin's TOML reader, `il_notify_argv`). Rejected: a wider regexp
  (quoted keys, escapes and dotted forms are TOML's to parse, not a grep's). Found while checking: the notify line's
  presence check (`install-lib.sh:675`, `grep -qE '^[[:space:]]*notify[[:space:]]*='`) misses `"notify" = [...]` the
  same way and would add a second root `notify`; the same one `tomllib` read answers both keys, so it is fixed there
  at no extra code, and the quoted-key test input carries a quoted `notify` too.
- Update path: rung 3, the platform's own `codex update`. Rejected: detecting npm / Homebrew from the binary's path
  and running each installer (the owner's Codex is the standalone installer, which that would miss; Codex already
  holds this table).
- Latest version: rung 5, one `curl` of GitHub's releases/latest for openai/codex (the page Codex itself links), tag
  stripped to the version. Rejected: `npm view` (needs npm, wrong for standalone/brew), `$CODEX_HOME/version.json`
  (Codex's own cache, stale once the startup check is off), `brew outdated` (brew only).
- Updater bound: rung 3, GNU `timeout` (already used by the plugin, e.g. `scripts/seat.sh:438`, and `coreutils` is
  required: `stat -c`): TERM at 300 s, KILL 10 s later. `timeout` signals its own process group, so an installer's
  children are stopped too. Output goes to a temp file, not a `$(...)` pipe, so a child that outlives the kill cannot
  hold the capture open.
- Prompt answer: rung 6, ~10 lines beside `fail_if_review_menu` in `seat.sh`. Always Skip, never "Update now": in a
  pane, Update now runs the installer and exits Codex, so the task is never taken. The update itself stays with
  setup/`update.sh`/the doctor, outside panes. This is a narrowing of the issue's "update, or skip": the log line
  names `update.sh` so the owner can update deliberately.
- Doctor: updates (the batch brief and issue 314 order it; their explicit order beats the older read-only contract in
  `skills/doctor/SKILL.md:9` and `README.md:100`, which this unit rewrites). A failed update is a `warn`, not a
  `FAIL`: `update.sh` runs `bash doctor.sh || back ...`, so a FAIL would roll the whole plugin update back over a
  Codex install that failed, and an old Codex still runs. Under `update.sh` the doctor runs after setup: after a
  good update it finds the latest and does nothing; after a failed one it tries once more (a second bounded try).
- Skipped: bun/pnpm specifics, a retry, a cache of the latest version, a lock around `codex update` (one run at a time).

setup, `update.sh` (through setup) and the doctor call. It prints one `codex:` line and returns 0 (latest or

- Installed: `codex --version` -> `codex-cli 0.162.1`, last field. No `codex` on PATH: prints nothing, returns 0
  (setup and the doctor already report a missing Codex for this profile).
- Latest: `curl -fsS --max-time 10 https://api.github.com/repos/openai/codex/releases/latest | jq -r '.tag_name // empty'`,
  leading non-digits stripped (`rust-v0.163.0` -> `0.163.0`). Unreadable: `codex: 0.162.1 installed, latest unknown
  (<curl's error>); not updated`, return 2.
- Not newer: `codex: 0.162.1, the latest`, return 0.
- Newer: `[ "$(printf '%s\n' "$i" "$l" | sort -V | tail -1)" != "$i" ]`.
- `plan`: prints `plan: would update Codex <i> -> <l> (codex update)` and runs nothing.
- Apply: `timeout --kill-after=10 300 codex update </dev/null >"$o" 2>&1` (`$o` a `mktemp` file, removed after;

- Installer: Codex's own `codex update` picks it (standalone, npm, bun, pnpm, Homebrew cask). "Manual or unknown",
  or an older Codex without `update`, exits non-zero and lands in the FAILED line above; the run continues on the

## 7. Established practice and the real bounds

Bounded waits on interactive prompts (expect-style: match the prompt, answer, re-check within a timeout, fail loud)
and updating a tool deliberately outside the session that runs it (the host project's
`check_for_update_on_startup = false`, and Codex's own `codex update`). The plan follows both. The one place the
issue allowed otherwise (answering Update now inside a pane) is not taken, for the reason in Decisions.

The waits this unit adds or relies on, each finite:

- The update: at most 300 s, then KILL 10 s later (310 s), once per setup run and once per doctor run; `update.sh`
  runs both, so at most twice. The latest-version `curl`: 10 s.
- A launched pane: the existing tui-idle wait, 120 s (`scripts/seat.sh:436`), then the new prompt wait, 15 s.
