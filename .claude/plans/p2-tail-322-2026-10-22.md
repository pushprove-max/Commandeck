# p2-tail-322-2026-10-22 -- every review finding, P0 to P3, blocks the merge

Tier: Plan + judge. LOCAL merge only. The unit closes the plugin issue that makes medium/low review findings
block the merge.
The owner's rule (batch brief) overrides the issue body: no P2 tail, no narrowed-pass acceptance, no
"Open at merge:" lines. The loop runs until the closing pass ends GO with nothing open. Only a finding
outside the unit's scope becomes a follow-up issue.

## Main answers

- Clearing a finding never turns a NO-GO into a merge: clearance is review context only, and the merge needs a pass that actually ends GO.
- `builder-codex-pass-decisions.test.sh` is in the plan, and its and `builder-codex-pass.test.sh`'s retired-routing assertions are reversed: a P2-only closing NO-GO routes to the closing pass, not a narrowed review.
- `merge-unit-local.test.sh` gets two concrete cases: a closing P1 NO-GO is refused with main unchanged, and a closing reply of only `VERDICT: GO` merges with rule `closing GO`.
- The whole exit-4 machinery in `merge-queue.sh` goes, with its stale text in `--help` and the docs and template, and a queue case pins it.
- The plan carries no issue references in any form.

## Decisions (ponytail ladder: the rung each part stopped at)

- The rule lives in the code that already decides the merge: `builder-codex-pass.sh --verify`. Rung 2
  (existing code). Rejected lazier: change only the rule text. The merge script would still accept the tail.
- A GO is "no finding at all". One regex in `session_proof` (`[P[0-2]]` to `[P[0-3]]`) turns any GO that
  names a finding into a NO-GO. The round file, the fresh-round hand-off and `orca-wait.sh` then route a
  fix round with no new code. Rung 5 (one line). Rejected: a separate P3 check in `--verify` only. The
  Builder would not get a fix round for a P3.
- One merge condition for the pass under merge, whatever its kind: it ends GO. The existing NO-GO die
  (~552) already says this for a first pass; drop its exemption for `fix` and `final` and it covers every
  kind. With `session_proof` above, a GO names no finding, so no per-finding check is left. Rung 5 (one
  line). Rejected: a GO-or-all-cleared condition. It merges a reviewer's NO-GO on main's word alone.
- "Cleared findings" in main's rulings stays as review context only. The pass prompt already hands them
  to the reviewer under the stated-limits head (~997), which now says "do not list it". A cleared finding
  never turns a NO-GO into a merge: the next pass must actually end GO. `--verify`'s clearance reading
  (`PP_CLEARED`, `CLEARED`, `uncleared`, `cleared`) then has no use. Rung 1: delete it.
- A reviewer that names a cleared finding again ends NO-GO, and the loop routes a fix round. The round
  cap (`builder-codex-pass.sh` ~784) refuses the round past the cap and reports to main; main can ask the
  owner and apply extra rounds through `review-cap.sh`. No merge waiver. No new mechanism.
- `reviewLoop.closingPass no` stays. It is the owner's setup choice, not the tail. Its narrowed pass
  merges only when it ends GO. Its chain check stays.
- Delete `file-open-findings.sh`, merge filing, `--area`/`--milestone`, exit code 4 (in
  `merge-unit-local.sh` and `merge-queue.sh`) and `pp_go_rule`. Nothing is open at merge any more, so
  nothing is filed. Each exists only for the tail's merge-time filing. Rung 1 (does it need to exist: no).
  Rejected: keep them as no-ops.
- Keep the main-watch `gate-<unit>` file's 4-line layout (key, rc, rule, line). Line 3 is no longer
  read once `pp_go_rule` is gone, but a layout change ripples into `orca-wait.sh`, its tests and the
  state files of a running main-watch. That costs more than one unread line. Rung 1 holds back here on
  purpose. Flag for cleanup.
- The dashboard (`dashboard.sh` ~442, `dashboard/app.js` ~248/778) still reads `open` from old
  finished-builds lines. History stays readable. New lines carry no `open`, which both readers already
  show as unknown. No change.
- Stated-limit findings: today the reviewer reports them as P3. P3 now blocks, so the prompt says
  "do not list it" instead. Rung 5. Rejected: a "P3 inside a stated limit" exemption in `--verify`. That
  is a second severity reading, the drift the rule is meant to end.
- Version: the next free minor at merge time. seat-signals-320-321 is planning in parallel. 0.28.0 if it
  is still free.

## 5. Catches (each changed flow step)

- Step 3 of the Builder brief: any closing finding goes back to step 2, and the next review is the closing pass. Catches: a P2 or P3 that the narrowed-pass tail merged and then filed as tech debt.
- `session_proof` reads a GO beside any finding as NO-GO. Catches: a reviewer that ends GO while it names a P3, which then merged as "open".
- One merge condition in `--verify`: the pass under merge ends GO. Catches: a closing pass, first pass or no-closing-pass narrowed pass that merges with a finding named, cleared or not.
- A review after any closing pass runs as `final`. Catches: a fix after a closing NO-GO that only a narrowed pass reads.
- The reviewer prompt drops stated-limit and cleared findings. Catches: a finding main already put out of scope that blocks the merge forever.
- `merge-queue.sh` stops on any exit but 0, 3 and 5. Catches: a queue that merges the next unit after a merge that did not finish.
