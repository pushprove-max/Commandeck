# quiet-wakes-318-2026-10-22 -- only actionable messages wake the orchestrator (issue 318)

Tier: Standard. One unit, issue 318 only. LOCAL merge. Changed-file tests plus the test files of every edited
script; no red proofs, no test-timeout raises. Closes issue 318.

## Main answers

- Own-echo suppression applies only to non-actionable echoes; an actionable message (done, failed/refused, question, decision, merge landed) always counts, whoever sent it, main's own handle included.
- The classifier and the watcher's unread recheck accept both recipient forms that reach main today, the run address and main's terminal handle (`scripts/to-main.sh`), and a test drives the real wrapper-to-inbox route.
- A successful automatic merge sends one actionable merge-landed message through the same post/batch path as every other actionable message; the digest-only expectation in `main-watch-auto-merge.test.sh` changes.
- Every held non-actionable message, main's own status notes included, shows in the next real wake's held block before it is acknowledged; heartbeats are the one exception and stay dropped.
- main-watch's typed wake for an actionable post goes through the same window as Orca's wakes; delivery and rebinding diagnostics keep their immediate handling.
- Every affected fixture is updated, and combined-path cases (t=0 and t=10 give one wake, exact expiry at t=60, a window holding only non-actionable messages gives no wake) assert total wakes across both sources and that every message is eventually shown.

## 2. The wake path today, and where each new part goes

Today:
- Orca types `You have N orchestration messages. Run \`orca orchestration check --run <run>\`.` into main's pane
  for any unread message to `run:<id>`, main's own sends included. Main spends a turn and runs
  `scripts/orca-wait.sh`, which drains (`check --run`, `:105-106`) and acks everything and prints what its KEEP filter
  keeps (`orca-wait.sh:216-274`): heartbeats, marker-less "turn complete" echoes, harness traffic and main's own status
  notes are hidden (to `hidden.jsonl`; heartbeats not even there).
- `hooks/cos-own-echo.sh` (UserPromptSubmit) drops that nudge with no turn spent, but only in the relay pane and
  only when the whole batch is the relay's own sends (`:24`, `:28`).
- main-watch types its own wake (`main-watch.sh:572`) after a post (`flush`, `:365`, delivered by `wake()` the same
  tick, `:1300-1303`) and, through `mail_wake` (`:489-503`), for unread non-heartbeat, non-heads-up mail to
  `run:<run>` not from main, older than `MAIL_S` (120 s) while main is idle. `wake()`'s unread recheck (`:549-550`)
  also reads only `run:<run>`.

Terminal-addressed mail and the drain: `to-main.sh` sends to main's handle, and issue 288's fixture
(`orca-wait.test.sh:150-169`) pins that orca-wait's `check --run` drain shows such a message (pp_detach's exit note).
So the drain needs no change; only the two counters below did not see that form. That Orca returns terminal-addressed
mail under `check --run` is taken from issue 288, not re-verified against Orca here.

New:
- `scripts/paths.sh`, new `pp_inbox_actionable <run> [main handle]` next to `pp_detach` (~337): prints, as one JSON
  array, the unread messages with `.to_handle == "run:<run>"` or (handle given) `.to_handle == <handle>`, whose
  `.type` is in `pp_option wakeKinds`, oldest `created_at` first. Any sender: no own-handle filter (main's own
  non-actionable echoes are already out by type). It reads `orchestration inbox --limit 500 --json` as `mail_wake`
  does; it fails on no answer or a full page (the caller then passes the wake). A message with no readable
  `created_at` counts as past the window (fail open). One classifier for all three callers below.
- `hooks/cos-own-echo.sh`, new main-checkout branch (git-dir equals common-dir), before the relay branch. Main's
  handle is `ORCA_TERMINAL_HANDLE`; now is `COMMANDECK_NOW` (main-watch's seam name) else `date +%s`:
  - Orca's nudge (the general form `hooks/ruling-log.sh:108` matches; the run from the prompt, else `pp_run_file`):
    - no actionable message: `{decision: "block"}`, nothing acked; the notes stay unread and are held.
    - actionable, the oldest younger than `wakeWindowSeconds`, and main-watch running: block ("one wake when the
      window closes").
    - otherwise (window passed, window 0, main-watch down, or any Orca/jq failure): pass, and print the silent-wake
      line (part 3).
  - main-watch's typed wake (prompt starts `main-watch: `): pass and print the silent-wake line. main-watch gates it
    on the same window itself (next bullet), so it is not gated twice.
- `scripts/main-watch.sh`:
  - `MAIL_S` (`:55`) goes; one window, `WIN=$(pp_option wakeWindowSeconds)`. `COMMANDECK_MAIN_WATCH_MAIL_S` goes with
    it (no test sets it; tests set the window through `COMMANDECK_OPTIONS`, which the hook reads too).
  - `wake()` (~544-553): with no `diag` (line 4 of the wake file), the unread recheck becomes
    `pp_inbox_actionable "$RUN" "$MAIN_H"`: nothing actionable unread drops the wake as today; the oldest one younger
    than `WIN` keeps the wake file and returns (waiting is not a try). So a post's typed wake and a mail wake both
    land at the same window close as Orca's. A wake with a `diag` (Orca refused a send, `arm_diag` `:421-431`, and the
    run-use / rebinding fix text built at `:577-581`) is typed at once, as today.
  - `mail_wake` (~489-503): count with `pp_inbox_actionable "$RUN" "$MAIN_H"` (drop the inline jq at `:491-493`, with
    its sender and heads-up filters); arm when the count is non-zero, no wake is pending, main is idle, and the last
    mail wake (the `unread-since` file, rewritten at each wake) is at least `WIN` ago or absent. The window itself is
    `wake()`'s gate above.
  - `merge_collect` (~830-832): the merge-landed post in section 1; comment `:809-811` and `merge_start`'s `:837`.
  - `flush` (~353-356): `status` for the heads-up relay.
- `scripts/orca-wait.sh` (KEEP ~257-274, rule 6 ~244-251, print loop, header ~12-14): the wake kinds come in as a
  JSON array (`--argjson wake`, from `pp_option wakeKinds`). KEEP selects every non-heartbeat message whose type is not
  in the wake kinds (held), plus the actionable ones its current rules keep. The `own` rule and its `: exit [0-9]+$`
  exception go: their only target (main's own `status`) is now always held and shown. The print loop prints the
  actionable kept lines first, then `held notes (did not wake you):` and one rendered line per held message, as
  `cos-watch-inbox.sh:180` does; a heads-up still prints whole under `--full` (RENDER is unchanged). Held messages are
  in `kept`, so their bodies are saved and they are printed before the ack, and they leave `hidden.jsonl`. Heartbeats
  stay dropped: liveness pings, not notes.

One wake per window, with no poll loop: the first actionable message opens the window (its `created_at`, ISO
UTC, `fromdateiso8601`). Orca's nudges inside the window are dropped, and main-watch's typed wake waits in `wake()`.
The first wake at or after the close passes: Orca's repeat nudge for unread mail, or main-watch's tick. So a wake
comes between W and W + 60 s after the first message, and it carries everything that arrived meanwhile. When both
sources fire at the close, the second finds nothing actionable unread (the first wake's drain acked it) or main
working, and does not wake.

Catches lines for the added steps:
- Hook drops a nudge with no actionable message. Catches: a progress note, heartbeat or main's own echo costing a
  full main turn (the issue's three recaps in 90 s).
- Classifier has no sender filter. Catches: a merge failure or question main-watch sends from main's handle, or a
  pp_detach result, held forever as "main's own".
- Classifier reads both recipient forms. Catches: a to-main.sh question (sent to main's terminal handle) never
  waking main.
- Hook holds an actionable nudge inside the window. Catches: two actionable messages 10 s apart costing two turns.
- `wake()` gates a post's typed wake on the window. Catches: main-watch's own post waking main at once, then a
  second message 10 s later costing a second turn.
- Hook holds only while main-watch runs (`main-watch.sh --status`, exit 0), else passes. Catches: a done message
  stranded unread when Orca does not nudge again and no watcher is up.
- `mail_wake` wakes on the window. Catches: a held actionable message that never wakes main.
- `merge_collect` posts a landed merge. Catches: an automatic merge that lands with main never told.
- Held block in `orca-wait.sh`, own notes included. Catches: a held note that main never sees.
- Silent-wake line on every passed wake. Catches: the "Nothing is waiting on you." recap turn.

## 4. The two /plugin options

In `.claude-plugin/plugin.json` `userConfig`:
- `wakeKinds`: string, title "Wake kinds", description "Orca message types that wake main. Others are held and
  shown at the next wake.", default `"worker_done,escalation,question,decision_gate,merge_ready"`.
- `wakeWindowSeconds`: number, title "Wake window (seconds)", description "Actionable messages that arrive within
  this many seconds wake main once. 0: each wakes at once.", default `60`. If `manifest_ok`
  (`scripts/__tests__/plugin.test.sh:29`) refuses `number`, use a string picker `["0","30","60","120"]`,
  default `"60"`.

Reader: `pp_option` gets two cases at `scripts/paths.sh:819-826`: `wakeKinds) p=.wakeKinds d=<the default> ;;` and
`wakeWindowSeconds) p=.wakeWindowSeconds d=60 ;;`. That path reads the `/plugin` answer from the user settings
(`pp_config_option`), then the project's `commandeck.json` (no such key there), then the default. The hook,
main-watch and orca-wait call `pp_option wakeKinds` / `pp_option wakeWindowSeconds` by those literal names, which is
what `plugin.test.sh:41` counts as a reader. Unset: the default. Empty `wakeKinds`, or one that names no valid kind:
the default (an empty list would never wake main). A window that is not a whole number: 60.

`setup` does not ask either; `plugin.test.sh:48-71` gets rows `wakeKinds|"worker_done,...,merge_ready"|-` and
`wakeWindowSeconds|60|-`, and the count at `:72` goes from 36 to 38 (its label names the two wake options).

## 6. Established practice

Debounce (trailing edge: the first event opens the window, one delivery carries the batch), event filtering at
the consumer (the hook, `wake()` and `mail_wake`) and quiet producers (the two retypes). The plan follows all three.
One difference: the window's close is noticed at the next Orca nudge or main-watch tick, not by a timer at exactly W,
so the wake comes W to W + 60 s after the first message. A timer would be a new process and a poll loop.
